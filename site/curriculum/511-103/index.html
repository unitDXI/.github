About this course#

Open source runs much of modern AI, from the libraries you import to the models you download. This course teaches how that world works, socially as well as technically. You will learn how projects are governed and licensed, and how to use Git with confidence rather than by memorising commands. Most of all, you will learn how to make contributions that maintainers are glad to merge.

The course is hands-on from the start. You will practise on sandbox repositories, then finish by landing a real pull request in a project you choose.

Learning objectives#

By the end of the course you will be able to:

  • Explain Git’s data model and use it to recover from mistakes
  • Work with branches, merges, rebases and pull requests
  • Find your way around an unfamiliar codebase and run its tests
  • Understand common open-source licences and contributor agreements
  • Give and receive code review, and read CI results

What you build: a merged contribution#

Your artifact is a pull request, merged by the maintainers of an open-source project you don’t control. Documentation, tests and small bug fixes all count. A focused, well-explained change beats a large one.

Your contribution is complete when:

  1. It targets an active open-source project with an OSI-approved licence, and you are not a maintainer.
  2. It follows the project’s contributing guide, including any sign-off or licence agreement it requires.
  3. It links to an issue or discussion where you agreed the change with a maintainer before starting.
  4. Every review comment has been addressed, and the pull request is merged.
  5. You have posted a short write-up in Discussions covering what you changed, what you learned and what you would do differently.
