Contribute

Unit 511 is built in the open, and every part of it can be improved by the people who use it. Here is how to take part.

Take a course

Learn at your own pace, or join a cohort.

Propose or write a lesson

Improve a lesson or write a new one.

Become a mentor

Guide a cohort through one stage.

Share your artifact

Show what you built and get feedback.

Report a problem

Tell us about mistakes, broken links or code that fails.

Take a course#

  1. Pick a starting point in the curriculum. If you’re new, start with 511-101.
  2. Open the course notebook in Colab or on your own machine, and work through the lessons in order. To learn with a group and a mentor, apply to join a cohort.
  3. Post questions and progress in GitHub Discussions. Helping someone else counts as contributing too.

Propose or write a lesson#

Lessons are plain HTML files, one folder per lesson, and you don’t need a build tool to edit them. For small fixes such as typos, unclear sentences or outdated links, use the Edit this page on GitHub link at the bottom of any lesson.

To write a new lesson or rework an existing one:

  1. Open a discussion describing the lesson: its objectives, how it advances the course artifact, and the tools it uses. Agreeing the outline first saves everyone time.
  2. Follow the contributing guide. It explains the lesson template, the building blocks (callouts, quizzes, exercises, “Try it” sandboxes) and the checklist for publishing.
  3. Run every code sample yourself before opening a pull request. Examples must run for free on public tools.
  4. Open a pull request. A maintainer will review content, accuracy and accessibility.

Become a mentor#

Mentors support a small group through one stage. They review artifacts, answer questions and help learners find good first contributions. Mentors need experience in the stage’s subject and a few hours a week during the cohort.

  1. Introduce yourself in the Discussions “Mentors” category. Say which track or stage you could support and what you work on.
  2. Read the Code of Conduct. Mentors are expected to model it.
  3. A maintainer will get in touch before the next cohort starts.

Share your artifact#

  1. Publish your artifact in a public repository under an open licence. Credit any Unit 511 material you reused (see how to credit).
  2. Post a link in Discussions with a short description of what it does and what you learned.
  3. Review at least one other person’s artifact. Feedback is part of the curriculum.

Report a problem#

Found a mistake, a broken link, code that doesn’t run or an accessibility problem? Open an issue. Include the page address and what you expected to happen. For code, include the error message and your Python or browser version.

Please report security problems privately, as described in the organisation’s security policy, not in a public issue.

Contribution standards#

  • Original and credited. Write in your own words. Quote briefly with attribution. Only include images and code you have the right to share under our licences.
  • Vendor-neutral. Use freely available tools, and name alternatives when you name a product.
  • Accurate and current. Link primary sources. Mark facts that change over time, such as model names, limits and prices, with the month and year.
  • Accessible. Headings in order, meaningful link text, alt text for images, and no information conveyed by colour alone.
  • Licensed. By contributing, you agree to license your contribution under CC BY 4.0 (content) and MIT (code), and you sign off your commits (git commit -s).
